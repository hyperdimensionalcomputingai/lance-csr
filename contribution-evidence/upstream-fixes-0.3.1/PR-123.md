## Problem and change

`MATCH (p:Person) WHERE p.id = 99 RETURN count(DISTINCT p.id) > 0 AS present` can return `true` when no row matches, because DataFusion's statistics shortcut turns the empty distinct count into 1.

Construct a query-local frame that omits `aggregate_statistics` only when the logical plan contains a distinct count. Preserve the caller session, the other optimizer rules, its query planner and the deadline context. Execution, streaming and explain share the guard. Current main already supports aggregates inside comparison/CASE expressions; this PR does not duplicate that work.

Refs https://github.com/lance-format/lance-graph/issues/123. This is a lance-csr fix; it does not close the upstream issue.
